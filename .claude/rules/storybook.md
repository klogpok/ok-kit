# Storybook

- Storybook runs on `@storybook/angular`, the webpack framework, because the Vite one requires Angular 21. Its builders in `angular.json` need `experimentalZoneless: true` (otherwise the builder pushes `zone.js` into the polyfills), `compodoc: false` (compodoc is not installed) and, on the dev builder only, a `browserTarget` — it throws `AngularLegacyBuildOptionsError` when that option is absent, so it points at `ui-kit:build-storybook`, whose options are the same ones.
- The story files import the framework as `@storybook/angular-vite`. The name is mapped to `@storybook/angular` for TypeScript in `.storybook/framework.d.ts` and for the bundler in `main.ts`. The TypeScript side is a `declare module` and not a `paths` entry on purpose: the builder feeds the tsconfig to `tsconfig-paths-webpack-plugin`, which resolves before the alias and would hand webpack the type declarations. The package `@storybook/angular-vite` is not installed at all — the import name is kept on purpose, because the Angular 20 migration (ticket 17) forbade rewriting the story files. Keep writing `@storybook/angular-vite` in new stories; it is not a leftover to clean up, and a mass rewrite is a decision for the user.
- `.storybook/tsconfig.json` includes only the stories and the `.storybook` files; library code enters the compilation through the stories' imports. A broader `include` (`../**/*.ts`) makes the webpack build warn "is part of the TypeScript compilation but it's unused" for every `public-api.ts` no story imports. `main.ts` runs in Node, not in the bundle, so it is excluded there too and type-checked for ESLint through `.storybook/tsconfig.main.json`.
- Stop the Storybook dev server you started when you are done with it. `pnpm storybook` refuses to start while another one answers on ports 6006–6030 (`scripts/storybook-preflight.mjs` says why); start it through `pnpm storybook`, not `ng run` directly.
- Storybook writes args onto the `component` instance when an arg name matches a field. For directives this replaced signal inputs. Use arg names that differ from the class fields (see `tooltip.stories.ts`).
  Protected and private fields count too: args `time` and `current` replaced computed signals of `ui-time-input` and `ui-stepper` ("is not a function" once the list or the steps render).
- The docs snippet ("Show code") is derived statically and shows an "Incomplete snippet" warning when a story has args that its template does not bind and that are not component inputs, when the template reads `props` that are not args, or when args are not literals (`fn()`, `new Date()`). Put args only on the stories that bind them (others spread `...Default`), keep template state in literal args, and write `parameters.docs.source.code` by hand for dates, functions and service demos.
- Storybook dev runs components in JIT, which has declaration-order traps in component files. See `.claude/rules/components.md` ("Storybook JIT").
- Open states are play stories (`play`): `openStory()` in `scripts/storybook-pages.mjs` waits for the preview's `storyFinished` event, so `test-storybook` runs axe and `test-visual` takes the snapshot after the play function, and a play function that throws fails both. Use `press()` and `until()` from `.storybook/play.ts`: `userEvent` sends `keyCode` 0, which the CDK key managers ignore, and the `waitFor` of `storybook/test` logs every failed attempt as a console error. Call `expect` once, after the wait. See `select/select.stories.ts` (`ManyOptionsAtEnd`).
- New or intentionally changed stories need new visual baselines (`pnpm test-visual:update`); see `.claude/rules/visual.md`.
- Docs pages are MDX files in `projects/ui-kit/docs/`, one unattached page each: `<Meta title="Docs/<Page>" />`, never `<Meta of={...}>` (every CSF file already has an autodocs Docs entry through the global `autodocs` tag). Their order is `parameters.options.storySort` in `.storybook/preview.ts`; a new page goes into the `Docs` list there.
  - Import blocks from `@storybook/addon-docs/blocks` (`@storybook/blocks` is not installed).
  - `remark-gfm` is not installed, so a Markdown table renders as plain text. Write tables as ``<Markdown>{`...`}</Markdown>`` (also from the blocks) or as JSX tables; do not add the dependency without the user.
  - MDX 3 rejects HTML comments (`<!-- -->`); use `{/* */}`. A bare `{` or `<` in prose must be in backticks or escaped.
  - Text inside JSX tags is still Markdown: a `*` in `<code>--ui-control-height-*</code>` opens emphasis that runs across the next tags and breaks the build ("Expected the closing tag `</code>`"). Write such text as a string expression, `<code>{'--ui-control-height-*'}</code>`.
  - The density table of `docs/tokens.mdx` is generated: `pnpm tokens` rewrites it between `{/* density:start */}` and `{/* density:end */}`. Edit `tokens/build-tokens.mts`, not the table.
  - All canvases of a docs page share one document, and the preview decorator writes `dir`, `data-theme` and `data-density` onto `<html>`: a story with story-level `globals` (`input` `Hebrew`, icon `RtlFlip`, density `OpenListCompact`) can flip the whole page. Prefer stories whose RTL comes from a `dir="rtl"` wrapper in the template, and check the page in the browser. Play functions do not run in docs, so open-state stories show closed.
  - Docs pages follow the toolbar theme through `.storybook/preview.scss` (wrapper, canvases, prose) and the channel listener in `preview.ts`, which sets `data-theme`/`dir` on pages without a story, where the decorator never runs. Its prose rules exclude `.docs-story *`, so the stories inside a canvas keep their own styles. The prose stays LTR (the pages are English) and only `.docs-story` takes the RTL toolbar direction.
  - MDX is not in the `format`/`lint` globs, and the story scripts skip docs entries: `pnpm build-storybook` is the check. A text lives either in a docs page or in `projects/ui-kit/README.md`, never in both: move it, and link to the README instead of copying.
