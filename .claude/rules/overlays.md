# Overlays, CDK Menu and direction

- The CDK `Directionality` reads `dir` once at startup. An overlay must resolve the direction when it opens, otherwise it renders LTR after a runtime switch to RTL. A panel below a field gets this from `uiDropdownPanel` (next bullet); any other overlay calls `syncOverlayDirection()` from core itself (tooltip, popover, toast), or passes `direction` to CDK Dialog. Position presets also live in core (`core/overlay.ts`); do not copy them into a component.
- A field that opens a panel below itself uses `<ng-template [uiDropdownPanel]="origin" [open]="isOpen()" (closed)="close()">` (`core/dropdown-panel.ts`, exported as `ɵUiDropdownPanel`), not its own `cdkConnectedOverlay`: it reads the direction, the offset and the origin width when it opens, closes on Escape and outside clicks, and returns focus to `returnFocusTo`. `CdkConnectedOverlay` is its host directive, driven through the instance: assigning `open` does nothing (call `attachOverlay()`/`detachOverlay()`), and only the `offsetX` setter pushes a new `origin` and `positions` into an existing overlay, so assign those first; `minWidth` needs `overlayRef.updateSize()` on a reopen. That setter behavior is CDK 20 internals, not a contract; `core/dropdown-panel.spec.ts` guards it (reopen with a new offset and width).
- CDK overlays use the Popover API (top layer) by default, so `z-index` does not order them. Opening order does.
- CDK Menu only calls `preventDefault()` on Escape and closes the menu synchronously, so a host binding on `ui-menu` never runs and the overlay keyboard dispatcher also closes a surrounding dialog. `UiMenu` stops propagation from a listener registered in its constructor (before CDK Menu's).
- CDK Menu closes the menu synchronously inside the item click handler, and a link that is no longer in the page does not follow its `href`. `a[ui-menu-item]` wraps `CdkMenuItem.trigger` to keep the menu open during the click and closes it in a `setTimeout`.
- A directive cannot extend a component (NG0903). The shared base of the dialog and drawer containers is an abstract `@Component({ template: '' })`, because it extends `CdkDialogContainer`.
- The CDK places connected overlays in viewport coordinates from x=0, but the fixed overlay container starts after a page scrollbar on the left. Chrome draws it there in an RTL document inside an iframe (the Storybook manager), and every overlay moved by the scrollbar width. Each connected overlay adds `overlayOffsetX()` (core) when it opens. `uiDropdownPanel` does it for every field panel (select, multi-select, autocomplete, time-input, the datepickers); the others use `withDefaultOffsetX()` (tooltip, popover) or the menu positions. A new connected overlay that is not a `uiDropdownPanel` needs it too; check it in the Storybook manager in RTL, not in `iframe.html`.
- The CDK push (`withPush`) ignores that offset and measures the end edge without the start margin: a pushed overlay ran 7 px under a left scrollbar, or kept 0 or 16 px from an edge instead of the margin. `UiPopoverTrigger` wraps the CDK strategy with its push off and pushes the applied position itself (`UiPopoverPositionStrategy`, `pushOnScreen()` in `core/overlay.ts`, exported as `ɵpushOnScreen`). Wrap the strategy built by `createFlexibleConnectedPositionStrategy()` rather than subclassing it: a subclass leaves the public `withPush()` open and must call its constructor directly. The CDK applies itself again on a window resize without going through the wrapper, so the wrapper listens to `ViewportRuler.change()` too. Other overlays that push (tooltip) keep the CDK behavior. Headless Edge hides scrollbars: check a scrollbar case with `ignoreDefaultArgs: ['--hide-scrollbars']`.
- Never size an overlay with `100vw`: it includes the page scrollbar. Clamp to the pane, which is at most as wide as the overlay container. A percentage on a surface sized by its content resolves against a pane sized by that content, so put the margin on the pane (`.ui-dialog-pane`, or `updateSize({ maxWidth })` for a connected overlay as in `UiPopoverTrigger`), not in a `min(…, 100% - margin)` on the surface.
