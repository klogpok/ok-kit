# Getting started

`@vplans/ui-kit` is our in-house Angular design system: standalone, `OnPush`, zoneless-ready
components built on `@angular/cdk`, themed with CSS custom properties, RTL-aware and built for
WCAG 2.1 AA. This page takes an app in this monorepo from no kit to a first screen.

## 1. Point TypeScript at the sources

The kit is not published. Apps in this monorepo use it from source: the root `tsconfig.json` maps
the package to the sources, so `import { UiButton } from '@vplans/ui-kit/button'` works in every
project.

```jsonc
"paths": {
  "@vplans/ui-kit": ["./projects/ui-kit/src/public-api.ts"],
  "@vplans/ui-kit/*": ["./projects/ui-kit/*/public-api.ts"]
}
```

## 2. Check the dependencies

The app needs the peer dependencies of `projects/ui-kit/package.json` (`@angular/cdk`,
`@angular/forms`, …) in the same major version. The kit targets **Angular 20** (`@angular/cdk`
20.2 — the CDK's v20 line stops there). `@angular/router` is optional: only `ui-tab-nav`
(`@vplans/ui-kit/tabs`) needs it.

## 3. Add the font and the global stylesheet

The kit uses the font stack `Assistant, Roboto, "Helvetica Neue", sans-serif`. Assistant covers
Hebrew and Latin. `@fontsource/assistant` is already a dependency of the workspace (root
`package.json`), so there is nothing to install: add its weights together with the global
stylesheet (tokens, document defaults, typography) to the app's build options in `angular.json`.
`includePaths` lets app SCSS use the mixins with `@use 'ui-kit/styles' as ui`.

```jsonc
"styles": [
  "node_modules/@fontsource/assistant/400.css",
  "node_modules/@fontsource/assistant/500.css",
  "node_modules/@fontsource/assistant/600.css",
  "node_modules/@fontsource/assistant/700.css",
  "projects/ui-kit/styles/ui-kit.scss",
  "src/styles.scss"
],
"stylePreprocessorOptions": { "includePaths": ["projects"] }
```

If you only need the CSS variables and not the document defaults, use
`projects/ui-kit/styles/tokens.css`.

## 4. Register icons and the theme

Register the icons you use and apply the stored theme mode at startup. The theme options, the
no-flash script and token overrides are on the [Theming](?path=/docs/docs-theming--docs) page.

```ts
import { provideUiIcons, uiIconCheck, uiIconX, uiIconSearch } from '@vplans/ui-kit/icon';
import { provideUiTheme } from '@vplans/ui-kit/theme';

export const appConfig: ApplicationConfig = {
  providers: [
    provideUiIcons([uiIconCheck, uiIconX, uiIconSearch]),
    provideUiTheme(),
  ],
};
```

## 5. Build the first screen

Every component has its own secondary entry point for tree-shaking. Import from it, not from the
root:

```ts
import { Component } from '@angular/core';
import { UiButton, UiIconButton } from '@vplans/ui-kit/button';
import { UiFormField, UiHint } from '@vplans/ui-kit/form-field';
import { UiIcon } from '@vplans/ui-kit/icon';
import { UiInput } from '@vplans/ui-kit/input';
```

```html
<ui-form-field label="Search">
  <input ui-input type="search" />
  <ui-hint>Order number or customer</ui-hint>
</ui-form-field>

<button ui-button variant="secondary" size="sm" (click)="cancel()">Cancel</button>
<button ui-button [loading]="saving()">Save</button>
<a ui-button routerLink="/orders">Orders</a>
<button ui-icon-button label="Close" (click)="close()"><ui-icon icon="x" /></button>
```

A bare `checked` attribute is a compile error.

## Embedding into an existing app

An app that already has global styles of its own (Bootstrap, an Angular Material theme, a
background on `html`) and must not change its `angular.json` loads the kit from the component
that uses it instead of steps 3 and 4. Render `<ui-embed-styles />` once in that component's
template and provide the built-in texts there:

```ts
import { Component, LOCALE_ID, inject } from '@angular/core';
import { UiButton } from '@vplans/ui-kit/button';
import { UI_LABELS_EN, UI_LABELS_HE, provideUiLabels } from '@vplans/ui-kit/core';
import { UiEmbedStyles } from '@vplans/ui-kit/theme';

@Component({
  selector: 'app-action-weights',
  imports: [UiEmbedStyles, UiButton],
  providers: [
    provideUiLabels(() => (inject(LOCALE_ID).startsWith('he') ? UI_LABELS_HE : UI_LABELS_EN)),
  ],
  template: `
    <ui-embed-styles />
    …
  `,
})
export class ActionWeights {}
```

`ui-embed-styles` is a hidden, unencapsulated component whose stylesheet is
`styles/ui-kit-embed.scss`: the tokens on `:root` (so overlays get them too) and the layout
classes (`ui-stack`, `ui-cluster`, `ui-grid`, `ui-container`). Angular keeps the stylesheet in the
document while at least one component that renders it is on screen. `provideUiIcons()` is an
environment provider, so without access to the app's providers register icons with
`inject(UiIconRegistry).register([...])` in the component, or pass the icon itself:
`<ui-icon [icon]="uiIconCheck" />`. The stylesheet uses only relative `@use`, so a copy of the
kit compiles it without `includePaths`.

Left out, compared with `ui-kit.scss`:

- **The document defaults** (`_base.scss`: font, color, line-height and background on `:root`,
  the `body` margin, `box-sizing: border-box` on every element). They would restyle the whole
  host app. The kit expects `border-box`, which Bootstrap's reboot and most resets already set.
- **The typography classes** (`ui-display`, `ui-heading-*`, `ui-body*`, `ui-caption`, `ui-label`,
  `ui-code`, `ui-text-muted`). The host has its own.
- **The switch to dark tokens under `prefers-color-scheme: dark`.** The host decides its theme:
  only an explicit `data-theme="dark"` turns the kit dark. Inside such a region, set the text
  color and background yourself (`var(--ui-color-text)`, `var(--ui-color-bg)`); the document
  defaults that did it are left out.

What a host rule can still reach. The kit's components resist the usual global rules of a host:
their roots and overlay panels set `text-align: start` (Bootstrap's `body { text-align: left }`
would break RTL), the `label` and `svg` elements they render set their own margin, display and
vertical alignment, and their native inputs and icon buttons set their own font.
`pnpm test-host-css` checks this on every story with Bootstrap 4.6 prepended. Still inherited
from the host, on purpose:

- **`color` and `letter-spacing`** where a component does not set its own (plain text in a list
  option, projected text): kit text then matches the host's text around it.
- **The position of a component** in the host's own markup: an inline component, such as a
  button, follows the `text-align` of its parent.
- **Rules more specific than the kit's or with `!important`**, and rules on properties the kit
  does not set (for example `::-webkit-scrollbar` styles of scrolling panels).
