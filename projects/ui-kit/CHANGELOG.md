# Changelog

All notable changes to `@vplans/ui-kit`. The package is consumed from source inside the monorepo,
so versions mark review points rather than releases.

## Unreleased (popup listbox field)

### Changed

- **listbox (internal):** the dynamic combobox ARIA of the inner control of `ui-select`,
  `ui-multi-select`, `ui-autocomplete` and `ui-time-input` (`id`, `aria-label`,
  `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-required`, `aria-invalid`,
  `aria-describedby`) is set by one internal directive, `[uiComboboxControl]`, which reads the
  field through the new `ɵUI_POPUP_LISTBOX_FIELD` token. The rendered attributes are unchanged.

## Unreleased (file type icons)

### Added

- **icon:** file type icons `uiIconFileImage`, `uiIconFilePdf`, `uiIconFileText`,
  `uiIconFileSpreadsheet`, `uiIconFilePresentation`, `uiIconFileArchive` and
  `uiIconFileDrawing` (CAD/BIM).
- **file-upload:** each listed file shows the icon of its type, by the MIME type, else by the
  extension. `fileTypeIcon(file)` gives that icon; the `fileIcon` input (`UiFileIconFn`)
  overrides it. A rejected file keeps the alert icon.

## Unreleased (choice xl size)

### Added

- **checkbox, radio:** `size="xl"` on `ui-checkbox` and `ui-radio-group`: a 24px box or circle
  and a larger label, for emphasis. The new type `UiChoiceSize` (`@vplans/ui-kit/core`) is
  `UiSize | 'xl'`; `ui-switch` stays on `UiSize`.

### Changed

- **core:** `UiCheckableBase` no longer declares `size`; `UiCheckbox` and `UiSwitch` declare it.

## Unreleased (leading actions)

### Changed

- **select:** the internal classes of the "Add «…»" and "Select all" options of `ui-select` and
  `ui-multi-select` moved to the popup listbox: `.ui-select__leading` is now
  `.ui-listbox__actions`, `.ui-select__create` is `.ui-listbox__create` and `.ui-select__all` is
  `.ui-listbox__select-all` (styles in `listbox/listbox.scss`). An app that styles or queries the
  old classes must switch; `UiSelectHarness` keeps its methods.
- **listbox (internal):** the listbox controller owns the two leading actions ("Add «…»",
  "Select all") as data and applies their rules; the field passes `createAction` /
  `selectAllAction`. Removed: the `[uiListboxLeading]` slot of `ui-listbox` and the
  `leadingOptions`, `alwaysShown`, `passedOver`, `leadingShown` and `isIndeterminate` members of
  `UiListboxConfig`. The internal listbox harness finds the actions with `getCreateAction()` and
  `getSelectAllAction()`.

## Unreleased (client pilot)

### Added

- **theme:** `UiEmbedStyles` (`<ui-embed-styles />`), a hidden unencapsulated component that loads
  the kit into a host app that keeps its own global styles: render it in the component that uses
  the kit, no `angular.json` change. See Docs/Getting started → "Embedding into an existing app".
- **styles:** `styles/ui-kit-embed.scss`, the stylesheet it loads: the tokens and the layout
  classes, without the document defaults (`_base`), the typography classes and the
  `prefers-color-scheme: dark` switch (an explicit `[data-theme='dark']` still works). Its tokens
  file `_tokens-embed.scss` is generated by `pnpm tokens`; `ui-kit.scss` and `tokens.css` do not
  change.
- **scripts:** `pnpm test-host-css` runs every story with a host app's global CSS prepended
  (Bootstrap 4.6.2 and the VPlans client's html/body rules, vendored in `scripts/host-css/`) in
  light RTL, light LTR and with a focused button, and fails when it changes a kit element.
- **select:** `creatable` on `ui-select` and `ui-multi-select` (with `searchable`, for string
  values): search text that matches no option label and no selected value is offered as a first
  "Add «text»" option; picking it (click, or Enter while it is active) sets the text as the
  value of `ui-select`, or adds it to `ui-multi-select` and clears the search. A matching option
  stays active above it. A string value outside the list is shown as its own label or chip.
  Over `items` the option opens the set (`aria-posinset`) and sticks above a virtual list with
  "select all".
- **select:** `maxLength` limits the search text of a `searchable` select (`maxlength` of the
  field).
- **core:** the `create` label (`UiLabels`): "Add «text»", Hebrew `הוספת «text»` with the text
  isolated (FSI…PDI). An app that passes a full `UiLabels` object of its own must add it.
- **testing:** `UiSelectHarness.create(text)` searches and clicks the "Add «…»" option.

### Changed

- **select:** the search field of a closed `searchable` select shows the trigger's cursor
  (`pointer`, or that of a readonly or disabled field) instead of `text`; the text cursor
  returns once the list is open. The row that holds "select all" is now `ui-select__leading`
  (was `ui-select__all-row`, an internal class).

### Fixed

- **select:** a search that hides every option leaves the list without an active option. Before,
  the option active before the search stayed active although hidden, and Enter picked it.

- **all components:** a host app's global CSS no longer bends the kit. Component roots and
  overlay panels set `text-align: start` (`a[ui-button]` sets `center`, like a button), so
  Bootstrap's `body { text-align: left }` no longer moves form-field labels and hints or select
  values to the left in RTL. A table caption keeps `caption-side: top`, no extra padding and the
  table's text color (a reboot moves it to the bottom in gray). The labels of form-field, checkbox, radio, switch and segmented
  set `margin: 0` (the form-field label also `display: block`), so a reboot's
  `label { margin-bottom }` no longer adds 8px under them. The SVGs of icon, checkbox, spinner and
  tree and the avatar image set `vertical-align`, and the native inputs of checkbox, radio,
  switch, segmented and slider and the icon buttons of chip, number-input, file-upload and select
  set `font: inherit`. Nothing changes without a host stylesheet. The text `color` and
  `letter-spacing` are still inherited from the host where a component does not set them.

## Unreleased (popup listbox)

### Added

- **testing:** `getActiveOption()` on `UiSelectHarness`, `UiAutocompleteHarness` and
  `UiTimeInputHarness`: the option the keyboard is on (named by `aria-activedescendant` of the
  field), or `null` when there is none or the list is closed.

### Changed

- **select, autocomplete, time:** the popup list is the `ui-listbox` element of the new
  internal entry point `@vplans/ui-kit/listbox` instead of a `div.ui-select__panel`. The
  internal classes `ui-select__panel`, `ui-select__panel--virtual`, `ui-select__empty` and
  `ui-select__loading` become `ui-listbox`, `ui-listbox--virtual`, `ui-listbox__empty` and
  `ui-listbox__loading`; the `--ui-select-panel-*` tokens stay. Nothing outside the kit used
  these classes, and the harnesses do not read them.
- **select:** the internal exports `ɵUiOptionPanel`, `ɵUiOptionParent` and
  `ɵprovideUiOptionParent` are removed, and so is `ɵUiItemOption` (now internal to
  `@vplans/ui-kit/listbox`):
  `ui-select`, `ui-multi-select`, `ui-autocomplete` and `ui-time-input` no longer share an
  option panel; each creates the listbox controller (`ui-select` and `ui-multi-select` through
  their shared internal `UiSelectBase`, `ui-autocomplete` and `ui-time-input` directly on
  `UiFormControlBase`). `UiOption`,
  `UiOptionGroup` and `UiOptionItem` are still exported from `@vplans/ui-kit/select`.
- **select, autocomplete, time, datepicker:** the field panels open through one internal
  directive, `ɵUiDropdownPanel` in `@vplans/ui-kit/core`, instead of their own
  `cdkConnectedOverlay`. It reads the direction, the scrollbar offset and the field width when the
  panel opens, closes on Escape and outside clicks and returns focus. No API change.
- **time:** ArrowUp in an open list without an active slot goes to the last slot (it did
  nothing), as in the other fields. A list with no slots (`minTime` after `maxTime`) shows the
  "no options" row instead of an empty panel.
- **testing:** `UiOptionHarness.isActive()` reads `aria-activedescendant` of the field instead of
  the `ui-option--active` class. The result is the same.

### Fixed

- **autocomplete:** ArrowUp in an open list without an active option goes to the last option
  (it left no active option); ArrowDown goes to the first.
- **select, autocomplete, time:** the active option stays active when the `items` (the time
  slots) are recomputed as new objects with the same values, and its label, description and disabled state follow the new
  item.

## Unreleased (chip appearance)

### Breaking

- **chip:** chips look different by default (a visual change, no API removed). `ui-chip` and
  `button[ui-filter-chip]` are now `outline`: rectangular with the control radius and a border on
  the surface, and a selected filter chip is filled with the text color. The previous gray pills
  and blue-tinted filter chips are `appearance="soft"`; restore them app-wide with
  `provideUiChip({ appearance: 'soft' })`. This also changes the chips of `ui-chip-input` and of
  `ui-multi-select`.
- **tokens:** the chip tokens are split into shared ones and per-appearance groups.
  `--ui-chip-bg`, `--ui-chip-radius` and `--ui-chip-filter-*` are replaced by
  `--ui-chip-outline-*` and `--ui-chip-soft-*` (`radius`, `bg`, `border`, `filter-bg`,
  `filter-border`, `filter-hover-bg`, `filter-selected-bg/border/text`).
- **select:** `UiOption` exposes only its inputs (`value`, `disabled`, `label`), `getLabel()`
  (the CDK typeahead calls it) and the `Highlightable` methods. `active`, `selected`,
  `indeterminate`, `filteredOut` and `unavailable` are protected; `id`, the `disabled` getter and
  the filter state are the internal `ɵid`, `ɵdisabled` and `ɵfilteredOut()`. Read an option's state from the DOM or
  `UiOptionHarness` instead.
- **spinner:** `--ui-spinner-stroke-width` is now the final stroke width (its default includes the
  former `* 1.25`), so an override of it gives exactly that width instead of being multiplied by
  1.25. An app that overrides it gets a thinner stroke; multiply the override by 1.25 to keep the
  old look.
- **table:** `density` defaults to `undefined` instead of `'default'`: a table without the input
  follows its region and gets compact rows inside `data-density="compact"`. The
  `ui-table--default` class is set only for an explicit `density="default"`; bind it to keep a
  table at default density inside a compact region. A `[data-density='compact']` region
  re-declares `--ui-table-cell-padding-block` (new `--ui-table-cell-padding-block-default` holds
  the default), and an explicit `density` re-declares it on the table.

### Added

- **chip:** `appearance` (`outline` | `soft`) and `size` (`sm` | `md`) on `ui-chip`,
  `button[ui-filter-chip]` and `ui-chip-set`, resolved chip → set → `provideUiChip()` → the
  built-in `outline` / `md`. `sm` is the compact chip for tables and cards.
- **chip:** `tone` on `ui-chip` (`neutral`, `primary`, `info`, `success`, `warning`, `danger`):
  a tinted background with the tone text and no border. Tokens `--ui-chip-<tone>-bg/text`.
- **chip:** an icon in a filter chip (`uiChipIcon`) takes the primary color
  (`--ui-chip-filter-icon`), and the check mark takes its place while the chip is selected.
- **chip:** `provideUiChip()`, `UI_CHIP_DEFAULT_OPTIONS` and the types `UiChipAppearance`,
  `UiChipSize`, `UiChipTone`, `UiChipDefaults`. Tokens `--ui-chip-font-size-sm` and
  `--ui-chip-padding-inline-sm`.

- **tokens:** size and duration multipliers that sat in component styles are component tokens,

  `--ui-skeleton-duration`, `--ui-progress-indeterminate-duration`, `--ui-table-busy-duration`.
- **core:** overlay helpers `UI_DROPDOWN_POSITIONS`, `UI_DROPDOWN_POSITIONS_WITH_END_FALLBACK`,
  `UI_SIDE_POSITIONS`, `UI_OPPOSITE_SIDE`, `UiOverlaySide`, `sideOverlayPositions()` and

## 0.2.0 - 2026-10-06 (Angular 20 migration)

The library targets Angular 20 and Signal Forms is gone. Both are breaking: the package no longer
compiles or installs against Angular 21 or 22, and every binding written against the Signal Forms
API has to be rewritten as a Reactive or template-driven form. The sections below cover the
migration only; the component work listed under the phase headings further down is unreleased
alongside it.

### Breaking

- **forms:** Signal Forms support is removed from the library entirely - no entry point, no flag,
  no compatibility shim. `ControlValueAccessor` is the only forms contract: bind every control
  with `formControl`, `formControlName` or `ngModel`. `[field]` bindings, the `FormValueControl`
  implementations and every import of `@angular/forms/signals` are gone. Reactive and
  template-driven behaviour is unchanged: value in both directions, `disable()`, `readonly`, the
  required marker, `touched` on blur, and errors shown once a control is both invalid and touched.
- **forms:** custom controls now register through the `NG_VALUE_ACCESSOR` provider instead of
  assigning `NgControl.valueAccessor`. A consumer that subclasses `UiFormControlBase` must declare
  `{ provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => X), multi: true }` on its own
  decorator; Angular does not inherit `providers` metadata into a subclass that carries its own
  decorator.
- **core:** `injectControlState()` takes an `Injector` and resolves `NgControl` lazily, on the
  first `sync()`, because a control that provides `NG_VALUE_ACCESSOR` and injects `NgControl`
  eagerly is a circular dependency (NG0200). `UiControlState` keeps every member; `bound` is now a
  `Signal<boolean>` rather than a plain boolean.
- **stepper:** `ui-step`'s `control` accepts a Reactive Forms control only. The union with a
  Signal Forms field, and the branch that read validity out of it, are removed.
- **number-input / time / datepicker / file-upload:** a parse error is held in the component's own
  error collection instead of a Signal Forms transform. It is displayed as before and never
  reaches the consumer's form control, so typed garbage no longer makes the form invalid by
  itself.

### Changed

- **peer dependencies:** Angular 20 only. `@angular/common`, `@angular/core`, `@angular/forms`,
  `@angular/platform-browser` and the optional `@angular/router` are `^20.3.0`; `@angular/cdk` is
  `^20.2.0`, the last line the CDK published for v20. `rxjs` stays `^7.8.0`. Angular 21 and 22 are
  no longer supported.
- The package name is unchanged: `@vplans/ui-kit`.
- **tooling:** TypeScript 5.8, Vitest 3, ESLint 9 with angular-eslint 20, ng-packagr 20. The
  library remains zoneless; tests and the playground provide `provideZonelessChangeDetection()`
  explicitly, since Angular 20 is zone-based by default.
- **storybook:** the workbench builds through `@storybook/angular` (webpack) instead of
  `@storybook/angular-vite`, which has no Angular 20 release. Stories, autodocs and the visual
  baselines are unchanged - every story renders pixel-identically. Hot module replacement in the
  dev server works as before.
- **tooling:** coverage thresholds are checked by `scripts/check-coverage.mjs` at the end of
  `pnpm test:coverage`, since the Angular 20 unit-test builder has no threshold option. Branches is
  80 instead of 90: Vitest 3 counts branches on the compiled output, so the same suite reads 81%
  where Vitest 5 read 93%.

  `UiSegmentedHarness` and `UiButtonToggleGroupHarness` in testing.

  `disabled`) gives the options as data instead of projected `ui-option`s. From
  `virtualThreshold` items on (100 by default) the list is a `cdk-virtual-scroll-viewport` that
  renders only the options in view; the keyboard, typeahead, search and "select all" still reach
  every item, `aria-activedescendant` names the active option once it is rendered, and each

  scrolls, and "select all" stays at its top while the rows scroll under it.

  `*cdkVirtualFor`: `aria-rowcount` on the table and `aria-rowindex` on each rendered row, a

  viewport.
- **tree:** new entry point with `ui-tree`, an APG tree view on CDK Tree over nested data
  (`childrenWith`, `keyWith`, `displayWith`). `selection` is `none`, `single` (the key of one

- **labels:** `noItems`, `loadFailed`, `retry`.
- **core:** `UiControlState.writeDerivedValue()` writes a value the control derived itself to the
  bound control and an `ngModel` binding without marking the control dirty.

## Phase 5: second audit

### Breaking

- **radio:** `compareWith` is called as `compareWith(option, selected)`, like `ui-select` and
  `ui-multi-select`. It was `(selected, option)`. It is typed `(option: T, selected: T) => boolean`
  on all three controls and is never called with `null`: a `null` value matches only `null`.
- **tokens:** unused tokens are removed: `--ui-color-text-subtle` (use `--ui-color-text-muted`, the
  same value), `--ui-color-primary-subtle-hover`, `--ui-color-info-contrast`,
  `--ui-color-info-subtle`, `--ui-color-info-text`, and every `--ui-z-*` except `--ui-z-sticky`
  (overlays use the browser top layer, so z-index does not order them).

### Changed behavior

- **select / multi-select:** `searchChange` also emits `''` when the list closes after a search.
- **datepicker:** a two-digit year is the one within 50 years from now (`85` → 1985).
- **calendar:** header buttons at `min`/`max` use `aria-disabled` and stay focusable.
- **button:** a disabled or loading `a[ui-button]` has no `href`; `loading` announces the
  `loading` label.
- **theme:** `provideUiTheme()` creates `ThemeService` on startup, so the stored mode applies
  right away.
- **tokens (dark theme):** `surface-hover` is the new `gray.750` (`#364054`) and `danger-text`
  is `red.200`, for visible hover on raised surfaces and AA contrast. The light skeleton uses the
  new `surface-emphasis` token.
- **tokens:** app overrides on `:root` now also win in system dark mode.

### Added

- `readonly` on every custom form control, bound by Signal Forms `readonly()`.
- `aria-describedby` passthrough on every custom form control.
- A `required` checkbox or switch is invalid until checked in Reactive and template forms
  (`provideUiCheckedValidator()`); `UiCheckableBase` shares the checkbox/switch logic.
- **select:** `displayWith`; the selected label survives server-side results; option size follows
  the select size; Home/End open the list.
- **dialog:** `provideUiDialog()` / `UI_DIALOG_DEFAULT_OPTIONS`; `confirm()` takes `injector` and
  `viewContainerRef`.
- **theme:** follows a mode changed in another tab.
- **icon:** 21 icons and the `UiIconName` type.
- **tokens:** `surface-emphasis`, `--ui-menu-max-height`, `--ui-badge-font-size-md`.
- **labels:** `required`.
- Tooling: coverage thresholds (`pnpm test:coverage`), the story accessibility check
  (`pnpm test-storybook`), ESLint `strictTypeChecked`, stricter Stylelint, playground smoke tests.

### Fixed

- **datepicker:** the parse validator no longer stays on the form control after destroy; a Signal
  Forms reset drops invalid typed text; the typed date stays LTR in RTL.
- **menu:** Escape in a menu no longer closes the surrounding dialog.
- **core:** overlays opened from `dir="auto"` elements take the page direction; runtime
  validators are picked up by custom controls.
- **toast:** new toasts no longer replay the entry animation or steal focus; keyboard focus is
  kept for every removal; mouse close and touch no longer pause the stack; timers pause in a
  hidden tab.
- **tabs:** a disabled tab link keeps no `href` after navigations; the selected tab scrolls into
  view.
- **switch:** the focus ring shows on an invalid switch.
- **a11y:** static `aria-label` no longer stays on generic host elements; the calendar marks only
  the selected day; the form-field label announces "required" when only the field is marked;
  pagination announces the range only for user changes.
- Smaller fixes in accordion, table, tooltip, badge, divider and radio (see `git log`).
